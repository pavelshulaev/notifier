# rover.notifier

Модуль для «1С-Битрикс: Управление сайтом» — оповещает администратора о необработанных ошибках и fatal error сайта по email, SMS или в мессенджер (Telegram/WhatsApp/MAX), используя штатные почтовые и SMS-события платформы.

Модуль не отправляет сообщения сам — он только перехватывает ошибку и инициирует стандартное событие Bitrix. Кто и куда доставит сообщение, решают уже настроенные на проекте интеграции: почтовый шаблон, SMS-провайдер или коннектор модуля «Сервис уведомлений» (messageservice).

## Возможности

- **Email и SMS/мессенджер** — два независимых события (почтовое и SMS), включаются и настраиваются отдельно стандартными средствами Bitrix.
- **Группировка одинаковых ошибок** — повторяющиеся ошибки не заваливают почту дублями: они копятся в очереди и раз в заданный интервал отправляются одним сообщением со счётчиком повторов. Одинаковыми считаются ошибки, совпадающие по классу, тексту, коду, файлу, строке, типу и источнику, — поэтому одна и та же ошибка из разных модулей не сливается в одну запись.
- **Критичные ошибки — без задержки** — Fatal error и необработанные исключения по умолчанию отправляются немедленно, даже если включена группировка.
- **Готов к работе сразу после установки** — автоматически создаются почтовый и SMS-типы событий и оба шаблона. Письма приходят сразу; SMS-шаблон создаётся выключенным и ждёт только получателя.
- **Источник ошибки в уведомлении** — модуль сам определяет, откуда прилетела ошибка: ядро, конкретный модуль (по его идентификатору) или код сайта. Указывать источник вручную не нужно.
- **Публичный API** для стороннего кода — `Rover\Notifier\Notifier::report()` позволяет отправить произвольное сообщение или исключение из кода сайта/другого модуля. Такие сообщения подчиняются общим настройкам: не отправляются при выключенном перехвате и попадают в группировку, если она включена.
- **Корректная деинсталляция** — модуль аккуратно убирает себя из конфигурации обработчика исключений, удаляет агент и таблицу очереди; события и шаблоны можно оставить по выбору администратора.

## Требования

- «1С-Битрикс: Управление сайтом» с модулем `main`.
- PHP 8.2 и выше.
- Для доставки SMS или в Telegram/WhatsApp/MAX — модуль `messageservice` с настроенным коннектором-отправителем (не обязателен для email-уведомлений).

## Установка

1. Установите модуль стандартным способом (через Marketplace или загрузкой в `/bitrix/modules/`).
2. После установки откроется страница результата установки с кнопкой **«Перейти к настройкам модуля»** — нажмите её, либо откройте настройки вручную: **Настройки → Настройки продукта → Настройки модулей → «Оповещения об ошибках на почту, по СМС и в мессенджеры»**.

## Настройка

На странице настроек модуля доступны опции:

| Опция | Описание |
|---|---|
| **Перехват ошибок включён** | Включает перехват ошибок сайта. После включения и сохранения письма об ошибках уже будут приходить на email администратора (email сайта по умолчанию) без дополнительной настройки. |
| **Группировать одинаковые ошибки** | Повторяющиеся ошибки не отправляются каждая отдельным письмом, а копятся и раз в заданный интервал отправляются одним уведомлением со счётчиком повторов. Рядом отображается количество ошибок в очереди и время следующей отправки. |
| **Интервал отправки группы, сек** | Периодичность отправки накопленной группы ошибок (по умолчанию 3600 = раз в час). Активно только при включённой группировке. |
| **Критичные ошибки отправлять сразу, минуя группировку** | Включено по умолчанию: Fatal error и необработанные исключения отправляются немедленно, не дожидаясь интервала группировки. |

После изменения настроек нажмите «Сохранить» или «Применить».

### SMS и мессенджеры (Telegram / WhatsApp / MAX)

Для доставки нужен установленный модуль «Сервис уведомлений» (`messageservice`) с подходящим коннектором-отправителем.

1. Перейдите по ссылке на SMS-шаблон для события `ROVER_NOTIFIER_ERROR_SMS` (ссылка есть под настройками модуля, либо раздел **Настройки → Настройки продукта → Почтовые и СМС события → Типы событий**).
2. Укажите в шаблоне телефон или chat_id получателя вместо значения по умолчанию `+7XXXXXXXXXX` и включите шаблон.
3. Для отправки через Telegram/WhatsApp/MAX дополнительно настройте нужный коннектор-отправитель в модуле «Сервис уведомлений».

### Email

Почтовый шаблон события `ROVER_NOTIFIER_ERROR` находится в разделе **Настройки → Настройки продукта → Почтовые и СМС события → Почтовые шаблоны** (или по ссылке под настройками модуля). По умолчанию получатель — email сайта; при необходимости получателя и текст письма можно изменить в шаблоне.

## Что попадает в уведомление

Шаблоны письма и SMS создаются при установке и содержат готовый набор плейсхолдеров:

| Плейсхолдер | Значение |
|---|---|
| `#MESSAGE#` | Текст ошибки |
| `#SOURCE#` | **Кто прислал:** «Ядро», идентификатор модуля (например, `rover.amosale`) или «Код сайта». Определяется автоматически |
| `#LOG_TYPE#` | **Что случилось:** тип ошибки по классификации Bitrix — `FATAL`, `UNCAUGHT_EXCEPTION`, `CAUGHT_EXCEPTION` и т.д. |
| `#CODE#` | Код исключения |
| `#FILE#`, `#LINE#` | Файл и строка |
| `#TRACE#` | Стек вызовов |
| `#COUNT#` | Сколько раз ошибка повторилась (при группировке) |
| `#HOST#`, `#DATE#` | Хост сайта и время |

Незаполненные поля (например, у сообщения, отправленного из кода без деталей) подставляются как «не указано» — в письме не остаётся пустых мест и нераскрытых плейсхолдеров. Шаблоны можно свободно редактировать: любые дополнительные поля, переданные из кода, тоже доступны как плейсхолдеры.

## Использование из кода

```php
use Rover\Notifier\Notifier;
use Bitrix\Main\Loader;

Loader::includeModule('rover.notifier');

// отправить готовое исключение: код, файл, строка и стек возьмутся из него сами
Notifier::report($exception);

// произвольное сообщение с дополнительными полями для шаблона
Notifier::report('Не удалось синхронизировать заказ', ['ORDER_ID' => 123]);

// при желании детали можно задать вручную
Notifier::report('Не отвечает внешний API', [
    'CODE' => 504,
    'FILE' => __FILE__,
    'LINE' => __LINE__,
]);
```

Источник (`#SOURCE#`) подставляется автоматически по вызывающему коду — модулю не нужно подписываться самому. Если автоопределение не подходит, его можно задать явно: `'SOURCE' => 'Импорт остатков'`.

Сообщения, отправленные через `report()`, проходят по общим правилам модуля: при выключенном перехвате ошибок они не отправляются, а при включённой группировке — попадают в очередь и уходят сводным уведомлением вместе с остальными.

## Деинсталляция

При удалении модуля можно отметить опцию «Оставить почтовые и SMS-события и шаблоны модуля» — тогда созданные и настроенные вами события и шаблоны сохранятся после удаления модуля.
